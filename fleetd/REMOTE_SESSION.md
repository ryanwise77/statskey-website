# Fleet Remote Session

Status: first implementation (v1). Replaces third-party remote-desktop
tooling with first-party code end to end. Last verified: 2026-08-19.

Fleet Remote Session opens a short-lived, end-to-end-encrypted screen tunnel
between two devices enrolled to the same StatsKey owner: a **host** (the
controlled machine, Windows-first) and a **viewer** (the controller). No
endpoint listens inbound; both connect outbound to a TCP relay that forwards
opaque ciphertext.

```
viewer (StatsKey desktop, controller device)
  │  account API (owner-authenticated): request / approve / end / list
  ▼
Workbench control plane ── fleetRemoteSessions/{sessionId}
  │  device API (device-signed): remote-session.poll / .approve / .activate / .end
  ▼
host (StatsKey desktop, worker device)
       │
viewer ──TCP──▶ statskey-relayd ◀──TCP── host
       (relay forwards AES-256-GCM frames; it never sees plaintext)
```

## Components

| Component | Location | Role |
| --- | --- | --- |
| Control plane | `workbench-backend/functions/fleetRemoteSession.js` | Mints session IDs + 256-bit session keys, records consent, distributes key material over authenticated channels. Disabled fail-closed unless `FLEET_REMOTE_RELAY` (host:port) is set. |
| Relay | `fleetd/internal/relay`, `fleetd/cmd/statskey-relayd` | Forwards frames between one host and one viewer per session. Stateless; no filesystem writes; no shell-outs. |
| Host runtime | `desktop/remote-session-runtime.cjs` | Polls the device API, approves under the consent model, captures the screen, encrypts frames, injects validated input. |
| Capture window | `desktop/remote-session-capture-preload.cjs` + `.html` | Hidden Electron window running `getUserMedia(chromeMediaSource: 'desktop')` → canvas → JPEG. |
| Input helper | `fleetd/cmd/statskey-inputd` | Tiny Windows binary listening on `\\.\pipe\statskey-input`; executes validated mouse/keyboard primitives via `SendInput`. |
| Viewer | `src/app/routes/FleetRemote.tsx` | Session list, explicit connect approval, canvas video surface, input capture, prominent red **End session** control. |

## Wire protocol

All signed structures use the Fleet canonical JSON + Ed25519 scheme
(`internal/canon`, `internal/keys`, byte-identical to
`desktop/fleet-auth-runtime.cjs`; pinned cross-runtime by
`internal/relay/hello_interop_test.go`).

### Handshake

Every frame is `uint32 big-endian length || byte type || payload`, length
covering the type byte, maximum 2 MiB. Control frames (type `0x00`) carry
canonical JSON and are bounded to 16 KiB.

The first frame an endpoint sends is a `RemoteHelloV1` control frame:

```json
{
  "domain": "statskey.fleet.remote-hello.v1",
  "sessionId": "rs_<32 lowercase hex>",
  "role": "host | viewer",
  "deviceId": "dev_<32 lowercase hex>",
  "publicKeySpki": "<device Ed25519 SPKI, base64url>",
  "ephemeralPublicKey": "<per-session Ed25519 SPKI, base64url>",
  "sessionKeyHash": "sha256:<base64url>",
  "issuedAt": "<RFC3339 ms UTC>",
  "expiresAt": "<RFC3339 ms UTC>",
  "signature": "<Ed25519 over canonical bytes without signature>"
}
```

The relay verifies, failing closed on any mismatch:

- the signature against `publicKeySpki`, and `deviceId` bound to that key;
- `expiresAt - issuedAt <= 10 minutes`, not expired, not future-issued
  (30 s skew);
- `ephemeralPublicKey` shape (the control plane records it in the session
  document; a future relay protocol may pin it);
- both sides present the same `sessionKeyHash` — the relay stores and
  compares only the SHA-256, never the key;
- one host and one viewer per session — a second host (or second viewer) is
  rejected (`duplicate_role`).

The relay answers `waiting`, then `paired` to both endpoints once both roles
are registered. Sessions close on peer disconnect, 10 minutes idle, 12 hours
maximum age, or handshake expiry while unpaired.

### Data frames

After pairing, endpoints exchange only encrypted frames; the relay forwards
them without inspection:

- `0x01` session control — canonical JSON under encryption (stream header,
  `session.end`);
- `0x02` video — JPEG frame bytes under encryption, host → viewer;
- `0x03` input — validated input events under encryption, viewer → host.

Frame payloads are AES-256-GCM under the 256-bit session key:
`nonce(12) || ciphertext || tag(16)`, random nonce per frame, AAD binding the
session ID and frame type so ciphertext cannot be replayed across sessions or
reinterpreted as another type.

The host's first control frame is the stream header: `{type:
"stream.header", width, height, scale, hostname, platform}`. The viewer
draws JPEG frames onto a canvas via `createImageBitmap` and maps pointer
coordinates back through the header dimensions.

## Security model

- **End-to-end confidentiality.** The session key is generated by the control
  plane and leaves it only over authenticated channels: the account API for
  the controller, the device-signed API for the worker (and only once the
  session is approved). The relay sees ciphertext and SHA-256 key hashes
  only; it cannot read, mint, or expand a session, and cannot turn
  view-only into input.
- **Consent.** A session is `requested` until approved. Approval happens
  exactly one of two ways: the signed-in owner approves through the account
  API (attended path), or the host device signs `remote-session.approve`
  while holding an active grant from the session controller covering the
  requested capabilities (unattended auto-approve path). Without a grant the
  session stays pending. The worker attaches a per-session ephemeral public
  key at approval; the approval receipt digest is recorded on the session.
- **Host visibility.** While streaming, the host always shows an
  always-on-top red "Remote session active" banner that ignores close
  requests until the session ends.
- **Input validation.** Viewer input is validated twice: the desktop main
  process bounds coordinates to the current stream header, restricts event
  types/buttons/key names to allowlists, and rate-limits (240 events/s token
  bucket); `statskey-inputd` re-parses every line (max 4 KiB, strict JSON,
  unknown fields rejected) and maps key names through its own fixed
  virtual-key table. The helper runs as the console user, never elevated;
  its named pipe uses the default DACL (current user + SYSTEM) and rejects
  remote clients.
- **Fail closed.** Unknown frame types, oversized frames, bad signatures,
  expired hellos/sessions, key-hash mismatches, duplicate roles, missing
  grants, missing relay configuration (`FLEET_REMOTE_RELAY` unset), and
  cross-owner access all reject or terminate.
- **Audit.** The control plane records session metadata (devices,
  capabilities, states, timestamps, approval receipt digest) — never video
  or input content. Retention: 90 days by default.

## MVP limitations (honest list)

- **JPEG over TCP.** One ordered byte stream means head-of-line blocking: a
  slow viewer stalls fresh frames. There is no delta encoding, no adaptive
  bitrate, and no audio. A v2 should evaluate QUIC/UDP with per-frame
  datagrams.
- **Single monitor.** The primary display only; the header carries one
  geometry. `MOUSEEVENTF_VIRTUALDESK` is set but multi-monitor coordinates
  are not mapped.
- **Windows host only for input.** `SendInput` injection exists only in
  `statskey-inputd` (Windows). `screen.view`-only sessions can run on macOS
  hosts (screen-recording permission required); the control plane rejects
  `screen.input` for non-Windows workers in v1.
- **No relay TLS.** The relay channel is plain TCP. Payloads are protected
  end-to-end, but a passive observer sees handshake metadata (session IDs,
  device IDs, timing). Front the relay with a TLS terminator that is itself
  trusted not to log frame bytes, or add TLS to `statskey-relayd`, before
  production exposure beyond a private network.
- **Session key custody.** The control plane stores the session key in the
  session document so it can deliver it to both sides. A control-plane
  database read of `fleetRemoteSessions` yields live session keys; the
  collection remains server-only, and a future version should move to
  ECDH-derived keys between the endpoints' ephemeral keys.
- **No rejoin.** If either side's relay connection drops, the session ends;
  a desktop restart mid-session cannot reattach (the host ends orphaned
  `active` sessions on its next poll).
- **Input latency.** The 5 s host poll plus JPEG frame cadence (default 8
  fps, max 15) is remote assistance, not remote gaming.

## Verified vs. needs on-host verification

Verified by automated tests in this change:

- Relay handshake auth (bad signature, expired hello, >10-minute lifetime,
  device/key mismatch, session-key mismatch, second host), frame bounds,
  unknown-type rejection, end-to-end byte forwarding through a real
  localhost relay, idle timeout, max session age, handshake timeout
  (`fleetd/internal/relay`).
- JS↔Go hello byte interop (canonical JSON, signature, timestamps, key hash)
  via a pinned fixture (`hello_interop_test.go`).
- Input helper command parsing, bounds, key allowlist, line protocol,
  oversize-line connection close (`fleetd/cmd/statskey-inputd`, run on any
  OS; the `SendInput` path cross-compiles for `windows/amd64`).
- Desktop frame encryption round-trip and tamper rejection, input
  validation, rate limiting, session state machine, pipe client bounds with
  a mocked pipe, relay client against a protocol-faithful mock relay, host
  runtime poll/approve/activate/teardown (`desktop/remote-session-runtime
  .test.cjs`).
- Control-plane request/approve/end/list flows, expiry folding, grant
  requirement (covering, revoked, expired, revoked controller), owner
  isolation, key-material release rules
  (`workbench-backend/functions/fleetRemoteSession.test.js`).

Needs on-host verification (not exercised here):

- `desktopCapturer.getSources` + `getUserMedia(chromeMediaSource:
  'desktop')` frame delivery inside the hidden capture window on Windows,
  including achievable fps and behavior across display sleep and lock
  screens. The capture path deliberately uses `getUserMedia` + canvas rather
  than `webContents.capturePage`, because `capturePage` on a hidden window
  does not repaint reliably without offscreen rendering; this choice needs
  on-host confirmation.
- `SendInput` behavior through `statskey-inputd`: absolute coordinate
  mapping on scaled displays (DPI awareness), wheel direction, and
  interaction with elevated foreground windows (expected: input silently
  fails against higher-integrity windows — acceptable, do not elevate).
- The non-closable indicator window against Alt+F4 and task-manager close on
  Windows (`closable: false` plus a `close`-event guard are both in place).
- Named-pipe DACL behavior for `\\.\pipe\statskey-input` under a
  non-admin console user.

## Packaging notes (owned by fleetd/packaging — not changed here)

- `statskey-relayd` needs a DEB (or droplet image) shipping the binary at
  `/usr/libexec/statskey-relayd`, the hardened systemd unit sketched in the
  `cmd/statskey-relayd/main.go` header (DynamicUser, no read-write paths,
  `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6`), and firewall opening
  for its listen port (default `:7447`, `STATSKEY_RELAYD_LISTEN`).
- `statskey-inputd` must ship inside the desktop app's resources at
  `bin/statskey-inputd.exe` (`remote-session-runtime.cjs`
  `resolveInputHelperPath`); build it with
  `GOOS=windows GOARCH=amd64 go build ./cmd/statskey-inputd`. The desktop
  fails closed (view-only) when the helper is absent.
- Set `FLEET_REMOTE_RELAY=host:port` on the Workbench functions environment
  and deploy the `fleetRemoteSessions` index before enabling the feature;
  the collection fails closed while the parameter is empty.

## JS hello fixture recipe

`internal/relay/hello_interop_test.go` pins a JS-signed hello. Regenerate
after any intentional wire change:

```bash
cd desktop && node -e "
const { generateKeyPairSync } = require('node:crypto')
const { createRemoteHello, generateEphemeralKeyPair } = require('./remote-session-runtime.cjs')
const { exportPublicKeySpki, canonicalJson } = require('./fleet-auth-runtime.cjs')
const device = generateKeyPairSync('ed25519')
const eph = generateEphemeralKeyPair()
console.log(canonicalJson(createRemoteHello({
  privateKey: device.privateKey,
  publicKeySpki: exportPublicKeySpki(device.publicKey),
  ephemeralPublicKey: eph.publicKeySpki,
  sessionId: 'rs_0123456789abcdef0123456789abcdef',
  role: 'host',
  sessionKey: Buffer.alloc(32, 7),
  issuedAt: Date.parse('2026-08-19T05:00:00.000Z'),
  expiresAt: Date.parse('2026-08-19T05:05:00.000Z'),
})))
"
```
